# tsr-learn

The calibration half of milestone M4 (Calibrate) of the TSR Decision Engine
(`docs/PRD.md` §B8, §B9, §B11 M4, §B12).

`tsr-learn` depends on `tsr-domain` and `tsr-store` only — never on `tsr-cli` — and is
**read-only** on the log. The one exception is the synthetic corpus generator
(`src/synth.rs`), which appends to its own fresh store; nothing else writes to a store.

It holds:

- `decision.rs` — the common decision event (`task_accepted_in_budget@v1`) as a pure view over
  the events: one row per commitment of a gated action, with its task, the commitment's event
  id and 0-based index, the action kind, and every forecast on the common event paired to it.
- `synth.rs` — the seeded, clock-free synthetic corpus generator (see below).
- `features.rs` — `features@v1`, the versioned feature spec carried in the bundle.
- `dataset.rs` — the dataset, the split and the data manifest.
- `probes.rs` — the three leakage probes (post-action events, label reach, the boundary).
- `head.rs` — the Tier 1 logistic head (hand-rolled, no ML framework).
- `isotonic.rs` — pool-adjacent-violators isotonic calibration.
- `support.rs` — the support count and the floor.
- `bundle.rs` — content-addressed bundles: fit, manifest, id, load, verify.
- `report.rs` — the controller against the generator on held-out rows.

## Usage

All of this is driven through the `tsr train` CLI (wired in `crates/tsr-cli/src/train_cmd.rs`).
Every printed number goes through `tsr_domain::Proxy` with its engineering name. The synopsis
follows `tsr train --help` and each subcommand's `--help`; `docs/m4-evidence.md`, generated by
`scripts/m4-evidence.sh`, prints those and runs every command below on the synthetic corpus with
its real output and exit code.

```
tsr train dataset [--store <db> | --events <events.jsonl>] --tasks <tasks.jsonl> [--labels <labels.jsonl>]
    [--by time|repo] [--calibrate <f>] [--holdout <f>] [--seed <n>] --out <dir>
tsr train fit <dataset-dir> --out <dir> [--support-floor <n>]
tsr train verify <bundle> [--rebuild <dataset-dir>]
tsr train report <bundle> --dataset <dir> [--seed <n>] [--json]
tsr train apply <bundle> --dataset <dir> [--side held_out|fit|calibrate|all]
```

### `tsr train dataset`

Builds the dataset, its split and its manifests from the log.

- `--store <db>` or `--events <events.jsonl>` — the log. With neither, the store at `TSR_DB`,
  else `.tsr/tsr.db` under the working directory. `--events` reads the `tsr task export` line
  format (`{"seq": <n>, "event": {...}}`).
- `--tasks <tasks.jsonl>` (required) — the task index: JSONL of
  `{ task, family, lineage, timestamp, clone_group?, tool_ms_ceiling? }`.
- `--labels <labels.jsonl>` — the labels input: JSONL of
  `{ task, criteria_met, diff_label, reviewer, recorded_at }`. `diff_label` is
  `accepted | rejected | disputed | null`; `null` means never reviewed. When omitted, no task is
  labelled (every row is unresolved).
- `--by time|repo` (default `time`) — the split rule. `time` is forward-time by the index
  timestamp; `repo` assigns whole lineages by a seeded shuffle. A task, and a clone group when the
  index names one, never crosses a boundary.
- `--calibrate <f>` / `--holdout <f>` (default `0.25` each) — the calibrate and held-out shares of
  the tasks.
- `--seed <n>` (default `0`) — the split seed.
- `--out <dir>` — the dataset directory.

Writes `rows.jsonl`, `split.json`, `data-manifest.json`, `features.json`, `events.jsonl` and
`tasks.jsonl` into `<dir>`. A row's id is `tsr_domain::Hash::of` over the commitment's event id,
the feature vector and the resolved label with its evidence ids. The data root hashes every row
id in canonical order; the training root the fit and calibrate rows. The split is made before
any fitting and has three sides: `fit` (the logistic head), `calibrate` (isotonic, the support
table, the population) and `held_out` (reports only).

Three leakage probes run before the dataset is written:

- **post-action events** — every row's features are recomputed from the log truncated before
  the commitment; any difference fails.
- **label reach** — extractors receive no label, by type, and a single feature that perfectly
  separates the fit slice's labels fails, named.
- **the boundary** — no task, clone group or (under `repo`) lineage on two sides, and under
  `time` every held-out task is later than every fit and calibrate task.

A caught probe exits 2 naming the probe and where it caught the leak, and the dataset directory
is not created: the evidence doc rewrites the labels so the family separates them, and `dataset` exits 2 with
`probe label_reach caught a leak at feature:family:calibrated`. The other two probes, and `fit`'s
re-run of all three over the `events.jsonl` and `tasks.jsonl` the dataset carries, are exercised
by `crates/tsr-cli/tests/m4_probes.rs` and the crate's unit tests, not by the evidence doc.

Every read of a held-out row, `dataset`'s own included, appends a line to
`<dir>/holdout-access.jsonl`; the split digest covers assignments only, so logging never changes
it.

### Input rules

Inputs are checked before the dataset is written. Each refusal below exits 2 and names what it
refuses; the evidence doc's "dataset input rules" section runs every one:

- `--tasks` is required (the argument parser names it): without it every task would silently
  become its own lineage with family `unknown`.
- A label whose `reviewer` is not the operator is refused naming the reviewer; a `diff_label`
  other than `accepted`, `rejected`, `disputed` or `null` is refused naming the file and line.
- A malformed JSONL line, a field of the wrong type or a task id that is not a hash is refused
  naming the file and line; a duplicate task id names the file, the line and the first line.
- `--by` must be `time` or `repo`; a share that leaves a side empty is refused naming the side.
- A `--store` that does not start with the SQLite header is refused naming the store.

A `--store` with a valid SQLite header but a corrupt body is **not** refused with exit 2: it exits
1 (`cannot open store <db>: sqlite: file is not a database`). That and the other current
exit-1 cases are listed under "Known limitations" in `docs/m4-evidence.md`.

### `tsr train fit`

Fits a bundle: the logistic head on the fit slice, then isotonic calibration of the common
event over the head's outputs on the calibrate slice. Exits 2 naming the count when fit and
calibrate hold fewer than 150 tasks with a resolved label (`too few mature episodes: 0 tasks with
a resolved label on fit+calibrate, need 150` for a dataset built without `--labels`); a family
with fewer than 30 stays outside the calibrated population, and its rows print `uncalibrated`.

`--support-floor <n>` records the operator's floor in the bundle (default 30).

Prints the bundle id: `tsr_domain::Hash::of` over each content file's digest and the manifest's
content fields — not the code commit, a timestamp or the evaluation report — so the same data
and seed give the same id.

### `tsr train verify`

Recomputes every digest and checks the manifest. Exits 0, or 2 naming the file: a one-byte edit
of `head.json` is refused naming `head.json` and both digests, and a manifest `state` other than
`draft` is refused naming `manifest.toml`. An edit to a manifest field the id covers is refused
naming `manifest.toml` and the field where it can tell (`seed`, `split_digest`, `feature_schema`
and `support_floor` against the content file that records them, `id` against the calibrator), or
else the three roots it could be (`data_manifest`, `training_root`, `source_root`); an edited
`[content_digests]` entry is refused as `manifest.toml` recording a digest the file does not
have. With `--rebuild <dataset-dir>` it retrains and compares ids. The manifest's `code_commit` is recorded provenance, not a verified
property: `verify` prints it labelled `code_commit (recorded, not verified)=<value>` and accepts
any value (edited to `deadbeef`, it exits 0 and prints that value).

### `tsr train report`

Scores, on held-out rows with a resolved label, the controller's calibrated `p` against the
generator's raw `p` for the same commitment: Brier, log loss (clip named and printed) and
reliability (10 equal-width bins with counts) per forecaster, per family and for the bundle.
The operator's raw `p` is scored beside them where recorded. The paired difference, controller
minus generator, is taken per task with a 90% cluster-bootstrap interval over repository
lineage (2000 resamples, seeded), `INCONCLUSIVE` when it spans zero (and `interval n/a` with
fewer than two lineage clusters, which no report in the evidence doc has). Uncalibrated rows are
excluded from the pair and counted.

A calibrated number prints as `p` with its calibrator version (the bundle id's first 12 hex and
`features@v1`), a raw one as `raw p`, a missing calibrator as `uncalibrated`. Families and
forecasters are listed in name order, never by score. The report is also written beside the
bundle as `<bundle>.report.json` (and `<bundle>.report.txt` without `--json`). A dataset that is
not the bundle's is refused with exit 2 naming both split digests.

### `tsr train apply`

Applies the bundle to a dataset's rows and prints one line per row, in row-id order, then the
row count. `--side` selects the rows: `held_out` (the default), `fit`, `calibrate` or `all`. Real
output, from the "apply --side fit" block of `docs/m4-evidence.md` (rows 8 to 10 of 696 and the
last line):

```
$ ./target/m4-evidence-fresh/debug/tsr train apply ./target/m4-evidence-work/m4-synth --dataset ./target/m4-evidence-work/m4ds --side fit
...
row 03106434b97f5ddfaff46c3f57cf3e9c60d4a71c2c07863d2ec32284a0b52f99 family underconfident raw p=0.930926 p=0.916667 (22b26e5e9bb4 features@v1) support=32
row 037714b20b9d10889fe460f04c187d223f5ea95bc8157ff3a0f56d27e185b868 family rare raw p=0.610656 uncalibrated support=8
row 0382a691d49660330199a62ca32622532ca8d0a3223a042aae2134e20d9904da family calibrated raw p=0.945463 p=0.916667 (22b26e5e9bb4 features@v1) support=17
...
rows=696
```

`raw p` is the logistic head's output for the row, before calibration. `p` is the calibrated
probability with its calibrator version, or `uncalibrated` (and no `p`) when the row's family is
outside the calibrated population — `rare` here. `support=<n>` is the number of fit- and
calibrate-slice episodes of the row's family whose every feature lies within the spec's window
of the row's.

`apply` refuses, with exit 2, a dataset that is not the bundle's (naming both split digests), a
tampered bundle (naming the file and both digests) and a tampered row (naming the row id and the
recomputed id).

## The bundle layout

`tsr train fit` writes a bundle directory (e.g. `models/<name>`) containing:

| file | content |
|------|---------|
| `manifest.toml` | the data-manifest digest (data and training roots), feature-schema version, code commit (`TSR_CODE_COMMIT` or `"unknown"`), seed, calibrator, thresholds (the support floor), the split digest, the source root, the state (`draft`) and the id |
| `head.json` | the logistic head: weights, bias, the L2 penalty and the iteration count |
| `isotonic.json` | the isotonic breakpoints |
| `features.json` | the `features@v1` spec: feature names, numeric widths, the fit-slice standardization statistics and the learning rate |
| `split.json` | the split assignments and its digest |
| `support.json` | the support floor, the calibrated population and the support index |

A bundle is written once, as `draft`; the evaluation report sits beside it naming the id. State
transitions and git tags are M5's. Coefficients and breakpoints live only in the bundle —
nothing writes a fitted parameter to the log or the store.

## The synthetic corpus

`src/synth.rs` generates `fixtures/m4/` deterministically. Regenerate with:

```
TSR_REGEN_FIXTURES=1 cargo test -p tsr-learn --lib synth::tests::regen -- --nocapture
```

`crates/tsr-cli/tests/m4_corpus.rs` regenerates into a temp dir, asserts byte-identity with
`fixtures/m4/`, and asserts every fixture session satisfies all of `tsr_cli::reconstruct`'s
invariants. The true acceptance model, each family's distortion, the seed and the counts are
documented in the module header of `src/synth.rs`.

Every number produced from this corpus is **synthetic**. The real exit evidence — controller
Brier below generator Brier on the held-out part of M3's mined corpus, and the support floor
set — waits for lanes 04 and 05 to merge and for the operator's runs. `docs/m4-evidence.md` is
generated by `scripts/m4-evidence.sh` (`bash scripts/m4-evidence.sh > docs/m4-evidence.md` from
the workspace root, then the prose between blocks) and shows the synthetic corpus's numbers as
the binary prints them.
