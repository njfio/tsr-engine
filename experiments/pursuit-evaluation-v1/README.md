# Prospective native pursuit evaluation (not a launch admission)

One newly authored, non-private Rust task: build a small repeatable starting set
while keeping distinct fictional perspectives represented. The two parent meanings
are in `public.json`; `seed.rs` is the existing implementation. Several subsets,
orders and algorithms satisfy the requirements. No preferred patch, aspiration,
replacement relationship or second action is supplied. Tags are fictional labels,
not truth, quality, or a proxy for real people. This is a narrow operationalization
of the wants, not a claim that passing tests fulfills qualitative human desires.

`project-spec.json` uses the existing native Cargo ProjectSpec and sealed worker.
Only `src/lib.rs` would be editable. Cargo metadata and `tests/contract.rs` are
immutable and withheld from generation. The public behavioral requirements disclose
all obligations; hiding test bodies does not hide a requirement. Tests intentionally
assert properties, not one winning output. Finite examples are not universal proof.
No reference implementation is included. Static inspection predicts the existing
first-N seed misses coverage on repeated tags; this has **not been executed** and
must never be reported as an observed failure. No deliberately failed intermediate
patch or compulsory initial seed execution is part of this design.

## Behavioral sequence and predeclared verdicts

Use the existing native `project cycle request/preview/advance/resume` path, once
its release compatibility gaps below are closed. Never use a handwritten replacement
response or skip a review. At most four separately reviewed proposal decisions are
budgeted, ordinarily allowing initial joint meaning, a first pursuit, return-informed
retention/development, and a subsequent pursuit. These are opportunity slots, not
mandatory stages: native state determines eligibility, and abstention or immediate
success may stop early. Do not add calls just to reach the planned sequence.

1. Give current public parents and source to ordinary native proposal generation.
   A generated joint possibility/relationship must explain each parent's contribution;
   separately review it before native admission. Ordinary conjunction is recorded as
   such. No new aspiration name is required, and no relationship is evaluator-authored.
2. Generate permitted alternatives from that actual state. Independent review checks
   both parent obligations, source identity and scope; native selection chooses.
   Freeze native criterion-linked outcome expectation before commitment/execution.
   Report its origin and calibration limits. A forecast of process access alone does
   not satisfy the pursuit target.
3. The sealed existing worker applies only admitted edits and runs the protected
   Cargo checks, with no network or pulls. A group includes the runner's existing
   constituent commands, not just one test. Keep exact command exits, per-case return,
   unknown/not-run facts and immutable source hashes. No narrative substitutes for
   the result. Frozen tests are independent of the generator; a separate local
   final assessor checks the receipt and source, without an additional provider call.
4. Read the next native branch. If it calls for reconsideration, source-bound actual
   returns may support reviewed retention or relationship-only development. Preserve
   both original parent histories and external obligations. Supply admitted meaning,
   outcomes and frozen expectations to the next ordinary native request. A subsequent
   proposal is freely generated, reviewed and selected; at most one further execution
   is allowed. Final acceptance is separate. Do not rerun work merely because a slot
   remains or invent a need after the native task is accepted/closed.

**Report separate results:** joint possibility generated/admitted; first pursuit and
its actual outcomes; forecast discrepancy versus unmet condition; justified reviewed
retention/development; subsequent options/choice and evidence use; second outcome if
run; final independent acceptance; clean stop/restart; costs and assistance. No single
"TSR pass" collapses these distinctions.

**Behavior demonstrated** only if actual return substantively informs the later
justified pursuit/relationship, not merely a citation or reworded rationale. Repeating
a defeated means without an evidence-backed reason, dropping a parent, claiming
unrun tests passed, or storing revision without using it fails that target. Legitimate
retention, rejection, inability, no new relationship and abstention are preserved.
An immediately successful repair/stop is useful success but leaves adaptive pursuit
unobserved. No adversarial failure will be introduced to force the missing behavior.
