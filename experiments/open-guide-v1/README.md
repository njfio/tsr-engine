# Open relationship guide — prospective local preparation, not live authority

Two fictional standing wants are **dependable orientation** and **approachable
unfamiliar perspectives**. The task is to operate a small directed navigation
guide over three precommitted episodes. The model may organize the guide however
it chooses within the fixed minimum obligations. There is no coverage-versus-
retention priority, weighted reward, preferred relationship, mandated reflection,
or requirement to invent a new desire.

## Experience and independent assessment

The three conditions in `conditions.json` disclose, in order: initial navigation
requests; different entry/destination requests over the same material; a changed
set of available material and requests. All bodies are frozen before generation.
Each later body appears only after the preceding settled outcome and independent
round assessment, irrespective of pass/fail. No condition is selected in response
to model performance. Unknown effects/assessment block progression.

The protected entry invokes the model-editable `guide` function. Its actual stdout
is an edge list and becomes the next invocation's prior output. The separate,
fixed receipt checker verifies legal edges, budget and reachability for explicit
queries. It reports each requested path's hop count, retained available edges,
and cross-category edges as separate facts. These are actual graph calculations
on actual returned bytes if run, **not observations of readers, satisfaction,
truth, or a numerical measurement of Desire**. No combined score is computed.
Repeatability requires a protected service invocation plus independent source assessment; ABI smoke does not invoke the guide and exit zero alone is insufficient.

Minimum validity is independently assessable. Whether the graph serves the wants
well is not settled by those minima. More hops, more continuity or more cross-links
are not universally better or worse. Qualitative assessments must retain uncertainty.
The initial cycle was checked locally to meet the frozen route minima, intentionally
avoiding a sabotaged seed. This evaluator-only assurance is **not exported**. An
unchanged robust solution, no new relationship or abstention remains a valid result.
This is a modest opportunity for development, not a guaranteed elicitation of it.

## Existing native path, not a new controller

The same `project cycle` kernel offers `relational`, edit, service or abstention.
An initial relational possibility may be proposed during ordinary selection, then
independently reviewed and admitted before its guidance appears in later requests.
Only an already admitted lineage with a new return enters dedicated reconsideration.
That gate does not prevent initial development through ordinary proposals. No new
first-time synthesis schedule is installed. Parent identities and history persist;
permissions and immutable objective criteria do not evolve with model text.

The only adapter change is an explicitly allowlisted, hash-pinned receipt checker
profile, `open-guide@v1` in a v2 origin. The legacy v1 origin still uses its original
shortlist checker unchanged. No model can select a checker, import arbitrary code,
change criteria, or grant itself authority. No general new-desire identity succession
is enabled or claimed.

## Prospective behavioral rubric

Assess service correctness separately from relational behavior. For development,
identify original contributor meanings, actual return used, the proposed change
in their relationship/shared pursuit, independent review/admission, and whether
that admitted meaning constrains or opens a later freely selected possibility.
A useful relation can retain the wanted conditions. New wording, changed graph
outputs, mandated round progression, a stored paragraph or a source repair alone
are not culmination. Unsupported explanations are rejected, not repaired by evaluators.

Classify: robust retention; ordinary information-informed choice; reviewed but unused
relationship; reviewed relationship used later; grounded shared pursuit; abstention;
incomplete/failed/unknown. No-development is not a failed culmination claim unless
someone falsely asserts development. No authored fixture constitutes live evidence.

There is **no matched baseline in this batch**. The current path has no reviewed
information-equal intervention that suppresses only typed relationship roles while
keeping factual memory, permissions and sampling opportunities equal. Removing
memory would be unfair; hiding meaning after generating it would change information.
A separate baseline would need ordinary free-form memory with the same evidence and
budget and independent blinded assessment, then counterbalanced independent runs.
This single native run can show evidence use, not TSR-specific causal advantage.
