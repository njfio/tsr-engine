## Known limitations

These are current behaviour, each shown by the block named after it:

- An `--out` directory the user cannot write exits 1 ("--out is an existing directory the user
  cannot write"), and `fit` and `apply` on a dataset the user cannot write exit 1 too ("fit and
  apply on a dataset the user cannot write"). Root writes a 0555 directory, so as root the script
  runs these commands as uid 65534 through `setpriv`.
- `fit` with `holdout-access.jsonl` as a directory exits 1 (`io: Is a directory`).
- `report` with `<bundle>.report.json` or `<bundle>.report.txt` as a directory exits 1 after
  printing the whole report (its stdout is byte-identical to the pipeline's `report`).
- The `--out` create probe leaves empty ancestor directories behind when a later step refuses:
  `dataset --out .../lim-out/a/b/c`, refused with exit 2 for an empty task index, leaves
  `lim-out`, `lim-out/a` and `lim-out/a/b`.
- `dataset --store` reads the whole file to check its header (`std::fs::read` in
  `crates/tsr-cli/src/train_cmd.rs`; no block can show the read itself), and a store with a valid
  SQLite header (`SQLite format 3\0`) but a corrupt body exits 1
  (`cannot open store ...: sqlite: file is not a database`), not 2.
- The default store path creates an empty store when none exists: with no `--store`, no
  `--events` and `TSR_DB` unset, `dataset` refuses with exit 2 but leaves `.tsr/tsr.db` behind,
  20480 bytes holding 0 events.
- `counts_digest` sits outside the bundle id: editing `unindexed_tasks` alone is refused (exit 2,
  naming the stored and the recomputed digest), but editing it together with its recomputed
  `counts_digest` is accepted, and `fit` prints the same bundle id as the unedited dataset
  (`22b26e5e9bb4...`).
- The synthetic corpus is not real sessions: every number in this doc comes from
  `fixtures/m4/`, generated by `crates/tsr-learn/src/synth.rs`.
