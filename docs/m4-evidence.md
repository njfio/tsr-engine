## Known limitations

These are current behaviour. The `--out` case is shown by the command above; the
`fit`/`apply`-on-an-unwritable-dataset case is listed without a probe because the sandbox runs as
root, so no mode bit makes a dataset directory unwritable (root writes a 0555 directory), and the
read-only filesystem that would is not writable enough to hold a dataset.

- An `--out` directory the user cannot write to exits 1 (shown above); `fit`/`apply` on an
  unwritable dataset also exit 1.
- `fit` with `holdout-access.jsonl` as a directory exits 1.
- `report` with `<bundle>.report.json` or `.txt` as a directory exits 1 after printing.
- The `--out` create probe leaves empty ancestor directories behind when a later step refuses.
- `dataset --store` reads the whole file to check its header, and a store with a valid header but
  a corrupt body exits 1.
- The default store path creates an empty store when none exists.
- `counts_digest` sits outside the bundle id: a consistent edit of a count and its digest is
  accepted.
- The synthetic corpus is not real sessions.
