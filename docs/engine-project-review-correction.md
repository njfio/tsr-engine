# Bounded runtime-review schema correction

The explicit v4 normal repair profile adds one prospective reviewer schema correction under the same two-correction budget shared with generator corrections. It reserves seven generator and seven runtime-review calls, four isolated execution groups, unchanged 8192 completion tokens/240 seconds per call and the existing synthetic-only payload limits. The normal accepted path uses five generator and six review calls; two shared corrections allow at most thirteen actual calls. Final independent acceptance remains separate.

Only known settled, metered, structurally invalid reports can receive a complete fresh response. The failed report's hash, bounded structural diagnostic, receipt and charge remain immutable. The new review ID and payload bind its predecessor, unchanged candidate/source/criteria and exact evidence catalog. The host never substitutes citations or edits a report to pass validation. Semantic rejection, unknown, abstention, recognized negative findings, uncertain completion, unknown billing, stale state and resource exhaustion stay terminal. Repository rules prohibit storing raw provider response bodies; their hashes and safe structural diagnostics are retained instead.

A durable correction marker consumes its shared slot before dispatch. Replay checks both the marker and corrected intent, including missing-marker and changed-admission failures. An uncertain corrected dispatch is not repeated. Old v1-v3 profiles do not gain correction authority; historical Trial20 remains unchanged.

Preparation for a fresh admitted trial adds `--review-schema-corrections` to the existing `--schema-corrections --final-payload-32k --model gpt-6-luna` driver preparation options. The separate runtime-review admission must be regenerated from that exact driver admission and current campaign manifest. Preparing files grants no dispatch; the existing exact-hash/effect opt-ins, campaign preflight and independent review still apply.

Independent review: [source and test assessment](../specs/lanes/reviews/engine-project-review-correction.md). Deterministic fixtures are not evidence of live model competence. The change addresses the observed inability to recover from a known reviewer schema defect; it does not guarantee a correct or accepting response.

Offline verification: the final focused batch passed 18 tests in 62.276 seconds (12 new boundary controls, one full native mixed-correction fixture and five existing generator-boundary tests). The existing runtime-review module plus the native fixture passed 12 tests in 144.996 seconds before the final narrow marker guard; the final focused batch reran that native flow with the guard. The native fixture counted thirteen shared authored provider calls and four cfg(test) worker groups, consumed one correction for each role, reached independent acceptance/clean stop and replayed with an identical ledger. No provider inference or actual target commands occurred during these checks. Diff check passed; no full-workspace sweep is claimed.
