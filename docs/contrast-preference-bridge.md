## Connected behavior

An ordinary browser proposal may now select `contrast_preference` with request-local
references to an applicable reviewed aspiration and authentic current Contrast.
Trusted transport owns the binding. Native validation requires current source and
requirements, explicitly unmet published criteria, at least two transitive original
contributors, and a current admitted aspiration. Unknown findings, surprise and
success alone are not Contrast. A generated hypothesis is not a new user preference.

A separate exact-response independent semantic review precedes
`project cycle preference-advance`. The transaction appends a real `Expanded` event
with Generator provenance and a `GeneratedPreferenceAdmission` with Council
provenance and the actual reviewer/generator identities. It never manufactures an
Operator opening. The immutable expansion and review remain separate from the
original acceptance criteria and authority.

The generated identity is available among subsequent composition contributors.
Its content, original contributors, originating Contrast/aspiration, exact source,
review and eligibility remain inspectable. Fulfillment stays **unknown**; no new
criterion, independent numerical value or permission is created. Parents and all
history persist. Contributor snapshots are flat: exact meaning plus immutable
meaning-revision or generated-admission references and original root IDs. Ancestor
records remain in the log rather than being recursively copied into each descendant.
Current contributor eligibility controls use without deleting the identity. Canonical parents and duplicate meaning/original-contributor checks prevent
simple permutation proliferation; semantic paraphrases still need independent review.

Same-identity public-meaning changes remain restricted to original acceptance
contributors, both identity and ancestry. Derived contributors can participate in
relational composition; this patch does not define a second same-identity revision
mechanism for them. Original acceptance mappings remain separate.

## Durable and public boundaries

The existing native cycle performs preview, owned review, atomic admission and
ordinary subsequent choice. No task-specific scenario driver or required synthesis
was added. The adapter journals exact transition input before admission and captures
the resulting public provenance. Interrupted capture uses an exact-input,
latest-transaction, source-bound read-only receipt; absence or ambiguity blocks.
Mixed Operator meaning and Council preference receipts retain distinct provenance.
Stop, pending effects and current session authority remain checked. No paid request
or execution is retried by this bridge.

Public projection accepts only journal-owned generated records or explicit frozen
import pins. Eligibility may change in the native fold; admitted content may not.
Foreign, missing or altered records and fabricated parent markers are rejected.
Source/requirements/history bindings and independent-review accounting remain in the
existing adapter. The ordinary-memory comparator gets the same facts but no formal
preference-admission action.

Browser text is preserved verbatim within the existing aggregate transport profile;
no 512-byte truncation or field gate is added. `Preference::from_admitted_text` only
constructs canonical identity; it does not authorize admission. Legacy
`Preference::new` and the generic ledger fold retain their existing 512-byte behavior.
Consequently extended generated identities exist in authoritative expansion events
and the authenticated **project fold**, while the legacy generic ledger view omits
oversized nodes. Short generated nodes remain non-open there. This is deliberately
not a claim of universal ledger selection or global identity-succession integration.

## Verification interpretation

Tests use authored proposals/reviewer responses and temporary native stores. The
multi-cycle native case admits a generated identity, admits later relational
composition involving it, changes temporary source as an explicitly authored
environment transition, returns an unresolved native assessment, and reconstructs
the preserved identity/history after restart. The authored adapter cases exercise
serialized generator/reviewer requests, admission, next-choice consumption and lost
result recovery. They do not demonstrate spontaneous model emergence or actual
player fulfillment; no new real browser execution is claimed by these cases.

Negative controls cover stale/foreign Contrast and source, unknown-only return,
semantic rejection, non-independent review, attempted authority fields, duplicate
parent permutations, unresolved resource effects, transaction rollback, Stop,
projection substitution and mixed-provenance recovery. The legacy oversized
Operator expansion remains ineligible.

Independent source review identified and corrected legacy-fold broadening,
mixed-receipt recovery and derived-ancestry projection defects. A development Python
run encountered source-pin drift while edits were still landing; its failure is
preserved and excluded from conclusive results. Conclusive logs and immutable source
fingerprints are in `target/contrast-preference-repair/`.
