# Bounded relational reconsideration after a return

This is the local fidelity slice following the native real-repair milestone. PRD B2/B2.1/B8 and the user's culmination correction require a relationship to remain capable of development after an expression is tested. A passing program check is neither proof that a richer aspiration is fulfilled nor a reason to invent further work.

The native project cycle now identifies an existing, active, nonsuperseded aspiration with new source-bound return evidence. Before final acceptance, it may request one advisory reconsideration even when mechanical checks pass. The response can develop or retain that lineage, or explicitly abstain. The existing relational validation and separate admission remain in use. Parents, original meanings and historical revisions are retained; withdrawn parents cease guidance.

The once-considered key names the lineage, scope, source, requirements and actual receipt/applicable judgment identities. Accounting events and ordinary state-head changes do not create another question. A current binding separately rejects stale state. A reviewed no-insight, rejection, unknown or abstention can consume the question without creating an action. Unknown judgment is attributed uncertainty, not a negative observation.

This does not reopen an accepted/closed task. Formal acceptance remains independent and available on its existing evidence; advisory development is not another acceptance gate. With no eligible aspiration or new question, the existing review/idle/stop path remains. Reconsideration itself cannot propose an executable alternative, grant permission, or run a follow-on action.

## Local boundary

The Python opt-in is `local-project-cycle@v2` with `advisory_profile: local-fixture-only@v1` and zero executions. The matching adapter profile is `local-semantic-return@v2`; it requires an injected transport and fixture ledger. Existing live admissions do not acquire this projection automatically.

The explicit semantic projection contains only a review identity, applicability and published unmet/unknown requirement IDs, with fixed attribution limits. It omits private review prose and aggregate counts. Source, frozen parent set, protected-file identities, implementation pins and bounded request size remain checked. It is preparation for a separately reviewed synthetic export, not permission to transmit new material.

Native interface on an already initialized local fixture:

```sh
target/debug/tsr engine --directory "$RUN" project cycle request
target/debug/tsr engine --directory "$RUN" project cycle preview --response RESPONSE.json
target/debug/tsr engine --directory "$RUN" project cycle advance --file REVIEWED_RESPONSE.json
target/debug/tsr engine --directory "$RUN" project cycle acknowledge --file ACKNOWLEDGMENT.json
```

Acknowledgment contains the exact current `binding` and `evidence_key`, an outcome (`no_new_insight`, `abstain`, `rejected` or `unknown`), bounded rationale and distinct supplied reviewer/generator attribution. Labels alone do not establish independence. The callback workflow supplies a separate reviewed result and stops after the advisory result; none of these commands authorizes execution or formal acceptance.
