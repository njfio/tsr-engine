## Smallest substantive missing capability versus missing proof

Representing and reviewing a changed relationship is **already implemented**, including
retaining an aspiration verbatim. No new aspiration field, selector or forced
reflection stage is warranted. The immediate missing proof is that a generated,
reviewed relationship does work in later pursuit beyond what the same model can do
with ordinary accumulated facts and suggestions. A legitimate result can be no
relation or no added value. The current evidence does not establish a code defect
preventing that result.

There is also a concrete full-cycle integration limit: qualitative inspection stores
access/content evidence, but does not freeze and resolve an expectation about the
information action and use the discrepancy in later choice. The generic adaptive
path has those mechanics, while the qualitative contract explicitly omits acceptance
forecasts. If extending this path, reuse the generic commitment/return mechanism for
a well-defined observable event (for example whether a chosen record answers an
explicit information question under independent evidence review, with unknown
allowed). Do not make retrieval success a proxy for desire fulfillment, invent
qualitative utility scores, or fit calibration from two readings. That design needs
a precise outcome contract; it is not justified as a silent audit-time patch.

## One prospective distinguishing evaluation — not authorized or prepared

Use a small frozen, held-out collection of newly authored non-private tasks with two
legitimate desires, several reasonable information/actions, and an external outcome
that can reveal a tension. Hold them out from prompt/schema tuning; independently
review and hash inputs, action scope and acceptance before any model result. Do not
reuse Cedar/Flint or prescribe a winning synthesis. Three paired tasks, two cycles
each, is a bounded exploratory evaluation, not a reliability estimate.

Compare two forks from each identical pre-action state:

- Full native relation condition: reviewed parent-linked relationship development
  can guide the next proposal, with unchanged parents/permissions and honest returns.
- Strong plain-memory baseline: same model, desires, raw observations, ordinary
  candidate memory, call/token budget, reviews and action menu. Supply the same
  reviewed relational text as an attributed memory note, but no native relational
  status/lineage guidance. The plain note must retain the informational parent links,
  provenance and review judgment; remove only operational native treatment. This
  prevents withholding useful information and then
  crediting structure for an information advantage. Baseline is an explicitly
  separate evaluation projection, never a forged authoritative history.

Equal observations apply at the fork. If actions diverge, preserve each arm's actual
returns; never manufacture identical subsequent evidence.

Randomize paired order and blind outcome judges to arm. Keep the same acceptance
oracle and compare substantive candidate/choice differences, warranted use of each
parent, source-grounded revision after return, actual outcomes/cost and valid stops.
Record failures and abstentions; no success-seeking reruns. A relation is not scored
by novelty or prose length: judges must identify how one parent's pursuit constrains
or enables the other, and what subsequent option changes as a consequence. Ordinary
conjunction, source comparison and unsupported novelty remain separate outcomes.

Use unchanged-input serialization/replay checks and equal-information checks locally.
If generated relations never arise, the result is no mechanism activation; if both
arms behave alike, no demonstrated structural contribution. If they differ, only
this small paired result is supported, not causal TSR superiority generally. This
comparison tests the added role of native relational structure; it does not isolate
all potential benefits of relational text itself.

The missing evaluation implementation is a small read-only baseline projection and
paired evidence collector, not a new controller. Before building it, trace where
relational attachment changes the candidate request and test equal-information,
source and authority invariants; if no meaningful intervention exists, report that
instead of comparing labels. Public attachment currently supplies advisory context;
if full versus flat only changes wrapping or labels, the experiment measures prompt
framing, not a distinct causal native mechanism. The expectation/return integration above is a separate
capability gap and must not be claimed solved by this comparison.

Concrete next step: specify that equal-information fork against existing generic
proposal interfaces and independently freeze one held-out task/oracle as a local
pilot, with no launch. No cap change or new export permission is requested here.
Any eventual live evaluation needs fresh scope, full call/review/correction envelope
and operation authorization; current operation capacity is exhausted.
