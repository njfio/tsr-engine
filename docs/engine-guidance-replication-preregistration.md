# Reversed-order replication preregistration

Frozen before dispatch, 2026-10-22. Repeat the two arms from
`engine-guidance-pair-preregistration.md` on exactly the same source snapshot,
parents, current A1, constraints and action schema. Reuse the frozen request bodies
byte-for-byte per arm. The only experimental change is dispatch order: unguided
first, guided second. Evaluation criteria are unchanged from the first preregistration:
action identities/attention, substantive relation to both parents, unresolved status,
prerequisite validity and unsupported requirement/fulfillment claims. No preferred
proposal or expected winner is supplied to the model or reviewers.

Exactly two new CheaperInference deepseek-v4.1-flash calls are admitted, temperature
zero, unspecified seed, 8192 completion tokens including reasoning, 240 seconds and
16384 payload bytes each. No retry, assessment, operation, adoption or revision.
If a terminal response is truncated or invalid, preserve that result and proceed to
the other arm only if completion/billing is known. An uncertain outcome stops the
admission and expires any remaining slot. No automatic retries or replacement samples.

Assign unrelated review labels R/S before dispatch; conceal mapping and order from a
fresh reviewer, who sees only the common world/schema/criteria and typed outputs (or
neutral unavailable-output markers). Keep timestamps, receipts, previous pair's outputs,
current A1 and treatment mapping out of that review packet. Unblind after assessment,
then compare both pairs without selecting a winner or dropping adverse observations.

The narrow question is whether the earlier difference in substantive-evidence
attention repeats. One reversed pair plus one initial pair has tiny N and cannot
separate all model/service variability from a stable guidance effect. No significance
claim, real social outcome or controller ranking is established. All original state
and source hashes must remain identical after fresh-process inspection. Prior evidence
and charges remain immutable; account/security settings and source scope are unchanged.
