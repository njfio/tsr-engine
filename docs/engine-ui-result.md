# TSR Studio local interface

This is a real React interface over the native browser-project engine, with a loopback-only Python backend. No new dependency installation, paid model call, game execution, host browser interaction, or campaign grant mutation occurred during this implementation.

## Delivered

- Conversation input enters real native feedback events in isolated derivatives; new briefs initialize native browser projects. Original games and histories remain unchanged.
- Native contributors, relationship history/status, source identity and returns are inspectable. Recorded rationale, review, execution and final decisions are shown as records, never hidden thoughts. Frozen expectation is explicitly unavailable in this view.
- Explicit Run prepares fresh native resource/admission/grant bindings automatically through the existing engine helpers. Fixed $10 / 200 calls / 100 isolated operations / 120-minute ceilings are enforced by the backend and existing launcher. Source-bound prior public context and authenticated review/assessment records carry forward without clipping; historical evidence does not become current-source evidence.
- Exact Host/Origin/CSRF, append-only input identities, durable Start identities, launch intent, uncertain-effect blocking and stop semantics protect against duplicate or unintended dispatch. Cancellation does not delete desires or settle unknown costs.
- Queued, native-admitted and provider-delivered are different states. Authenticated request/response association establishes delivery only, not causal learning. User input is attributed guidance alongside original contributors, not automatic desire evolution.

## Verification

13 local regression tests passed, including real HTTP→native feedback→read/reload, original preservation, quoted-input delivery binding, source-bound preparation→authored provider abstention→inert replay, duplicate IDs/Start, interruption after native mutation, tamper rejection, queueing on incomplete sessions and unknown-budget refusal. A final reviewer-found edge (second feedback before a fresh project's first Run) passed its targeted preservation regression (1 test, 9.3 seconds). No checks were skipped. Independent source review concluded with no blocking findings. All provider responses in these tests are explicitly authored fixtures in separate ledgers, not live evidence.

Six browser fixture checks passed in the existing pinned network-disabled non-root Chromium container: desktop rendering, blocked Run, CSRF-protected composition, recorded rationale view, 390px no-overflow layout and no JS errors. Screenshots in `docs/engine-ui-evidence/` are labeled authored fixtures. This browser test and the real loopback/native HTTP test are separate; no claim is made of a paid full browser-to-model run.

Initial development failures were corrected: empty-parent initialization, fixture-only adapter construction, sandbox socket access for local HTTP, and an insecure test-origin crypto assumption. The final application uses the loopback secure context, native initial guidance, durable journals and approved local test permissions. No security control was weakened.
