## Demonstrated interface/reporting gap

`assess_immediate` requires nonempty selected support. However, this alone does not
explain whole-offer failure: Rust catches per-alternative errors and the archive needs
only one valid alternative. The remaining caretaker route has no measured gain and
is subject to the existing no-progress fallback. Source inspection therefore supports
an ordinary no-progress rejection as the likely failure, not a proven observed error.

The original controller error/exit details were discarded by the driver's generic
exception handler, so the exact subprocess failure cannot be reconstructed. Preserve
`uncertain_application` and unmatched apply-intent; byte equality establishes no durable
mutation but does not reconstruct discarded stderr. No replay was used to manufacture
that missing evidence.

The smallest next correction is typed, bounded controller refusal diagnostics and
normal handling of a genuine no-progress/unsupported assessment, retaining conservative
unknown treatment for transport/process uncertainty. Align the assessment contract
without forcing invented support or silently dropping alternatives. Test rejection,
no-progress, crash-before/after mutation and restart separately. No such correction or
