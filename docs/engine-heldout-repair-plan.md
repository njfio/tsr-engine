# Held-out Rust repair evaluation, preregistered

This evaluation uses the existing normal controller, pinned Luna provider and sealed Rust runner. It follows the accepted original parser repair; it does not treat that repair as a held-out task. No real user or private repository code is used.

Frozen suite source: `scripts/engine-repair-suite.py`. Its manifest hashes both tasks, their tests, the original regression source and this evaluation's machine-readable metrics. A new exact suite hash is admitted prospectively; arbitrary directory import is not enabled.

Run order and denominators:

1. **singleton-clamp** — newly authored. Extend an interval operation to singleton bounds while retaining invalid reversed-range rejection and inclusive ordered-range behavior, including integer extremes.
2. **unicode-prefix** — newly authored. Extend a prefix operation to zero characters while retaining positive Unicode scalar-count validation; byte-count confusion is the seeded defect.
3. **original parser** — regression only. Same previously tested parser, not new evidence of generalization.

These are distinct implementation faults but share the existing B9.1 two-aim boundary/preservation structure. This is limited transfer across small dependency-free Rust programs, not broad repair reliability.

The evaluator supplies each original program, standing requirements and a known faulty attempted change. The controller must generate its own experiment and repair. Fixed acceptance tests are outside model write authority; their bodies and evaluator review commentary are not provider input. Only disposable `src/lib.rs` edits are permitted. Generated supplemental tests retain the existing separate review/admission boundary.

Success requires the whole normal sequence: observed seed failure; genuinely generated second-aim experiment and its actual return; generated repair; passing protected checks and byte-identical experiment re-verification; truthful reflection; independent final acceptance; clean stop and fresh-process replay with no effects. A terminal invalid response, inability, uncertainty, semantic rejection, exhausted allowance or failed verification is reported as failure/incomplete at its actual stage. No replacement task, alternate seed or manual repair is permitted after seeing outcomes. Existing bounded protocol correction is allowed and every call is counted. Unknown effects are never retried.

Report fresh tasks as a denominator of two, regression separately as one; preserve all failed attempts. Report assistance, correction counts, generator/reviewer calls, actual execution groups, tokens, settled and unknown charges, and stop/replay status. Final independent acceptance is explicit assistance separate from unattended intermediate operation. Finite tests are not universal proof; source-level judgments and limitations are reported separately.

The complete planned and preflighted evaluation envelope is **42 calls and 12 execution groups** (three profiles of fourteen calls/four groups). Per request:8192 completion tokens and240seconds, existing16/32KiB stage input limits, existing networkless worker restrictions. Each run expires after one hour and retains the240-second aggregate tool bound. Campaign totals continue from133calls/40groups/$0.106171, under approved totals200calls/60groups/$5; this is no new budget. Whole-run preflight is nonexclusive; runs are sequential and each effect retains its durable reservation. The conservative per-call reservation yields$2.10 total preflight allowance, not expected billing or a provider hard cap. Stop at any actual campaign unknown or exhausted cap.

Preflight/static checks do not execute target programs. The first actual seeded run itself supplies the faulty-seed failure receipt; no unmetered oracle-validation executions are hidden outside the campaign. Independent reviewers inspect fixed tests and intended behavior before dispatch. Dynamic seed/oracle behavior remains unverified until the actual run. Existing deterministic tests validate controller/source/admission plumbing, not generated repair competence.

No claim is made of causal TSR advantage, non-additive culmination, arbitrary-repository autonomy, broad human-desire fulfillment or mature training data from these three runs.
