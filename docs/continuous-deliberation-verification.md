# Continuous optional development: offline verification

The isolated implementation now supports optional independently reviewed development alongside an artifact edit or retention in one deliberation. Browser reconsideration may propose a new relationship, revise an existing relationship, develop an existing identity, or propose provisional/supported empirical wanting. Prior lineage is context, not a compulsory target. Retention, uncertainty and no development remain valid.

This implements the author's November 1 clarification prospectively. It does not establish spontaneous development, general autonomy, enjoyment, or comparative TSR benefit. No provider call or new live evaluation occurred. The paired experiment remains unchanged at `210b0d5c`.

## Transaction and provenance

One generated response contains an artifact component, optional development, and an explicit `independent` / `requires_development` dependency. Development receives its own independent review and atomic native admission first. The artifact component is then derived by changing only trusted state/attention metadata. Its code, expectations, action/contributor references and original response remain unchanged. An artifact edit receives a fresh independent review against the resulting state before execution. Native mixed executable/advisory batches remain forbidden.

Approval of one component never approves the other. Rejected development blocks a dependent artifact; an explicitly independent artifact still requires its own review. Rejected artifacts do not erase admitted meaning. Artifact retention can coexist with meaning development. Artifact-review abstention terminates, including after interruption; it is not silently retried for approval. Development-review abstention blocks development and a dependent artifact; an explicitly independent artifact may still proceed to its own review. A later authored sealed-browser test (9ba9c5de) covers an actual independent edit after development abstention: distinct artifact review, one passed execution, no generated preference or task acceptance, and inert restart. A rejected/unknown reconsideration retention assessment remains visible as `advisory_rejected` / `advisory_unknown`, with the exact judgment.

Derivations bind the original owned response, component, evidence basis, exact review and admission, unchanged source/obligations, and exact resulting parent/relationship rows. Later changes to the same identity cannot masquerade as this component's delta. Historical feedback authenticates the original response association and captured attention/source binding; it does not synthesize provenance from a self-consistent hash.

Native relationship admission and its receipt are atomic. Exact receipts recover interrupted local capture without re-admitting meaning. All admitted reconsideration kinds recover their controller decision marker. Pure local records and terminal values recover from their retained intents without callbacks. Missing authoritative receipts, unknown external effects, stale source and Stop remain fail-closed; recovery does not guess an external outcome. Accepted history is never deleted or rolled back to make the other component pass.

A new child becomes a native Preference with Council eligibility, unknown fulfillment and immutable ancestry. Subsequent decisions receive it. The host does not rewrite an original artifact's contributor references to claim that it selected a child which did not yet exist. Neither desire development nor stopping grants action authority, changes original obligations or withdraws retained desires.
