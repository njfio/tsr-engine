# Generation quarantine: disposal is not financial reconciliation

This prospective local policy can append a disposal record for a single unknown, tool-free browser generation. It never removes the unknown, releases its reservation, identifies a provider response, settles native usage, or grants a new session. Current policy deliberately keeps paid dispatch blocked while a charge ceiling remains unverified. It does not provide a financial-risk override.

The inspector holds both supported browser launcher locks before reading the exact hash-chained adapter prefix. It checks the sole pending dispatch, plain-text request shape, original campaign body/admission binding, exact native root/snapshot/scope, and the native outstanding reservation's request ID, body envelope, model and token bound. Native resource validation authenticates the resource CAS before read-only inspection. Active launchers, changed prefixes, tool-bearing requests, completed generations, unknown executions and any execution in the affected trial are rejected. The original native and adapter journals remain untouched.

The append-only campaign event permanently excludes the old trial/output from normal adapter transitions and new effects. A duplicate identical disposal is idempotent; substitutions are rejected. Financial fields remain unknown and committed. Any future permission to proceed needs a separately reviewed financial disposition and fresh source-bound derivative admission carrying prior calls, costs and deadline; this implementation does not silently invent that authority.
