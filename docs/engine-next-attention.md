# Admitted next attention

Run on an initialized project:

```sh
target/debug/tsr engine --directory RUN project attention
```

This read-only projection uses the original ledger selector (`lineage-half-retain@v1`),
not criterion-count ranking or a new value theory. It considers only currently
admitted task preferences with registered criteria or current semantic requirements.
Currently source-bound satisfied obligations are excluded, while unknown observations
remain unknown. Withdrawn/out-of-scope/unadmitted wants stay excluded. The trace retains
canonical preference identities, parents, observed state, support and exclusion reasons.
The factual root, source snapshot and resource-store root bind the report.

A pending commitment suspends selection. Closed episodes may still expose residual
attention, but require new admission. Resource capacity is reported separately for
model calls/tokens and tool time: zero inference allowance does not prohibit an
otherwise admitted verification. Reservations and stop states remain blockers.
Selection never creates goals, generates candidates, grants authority or executes.
Registered routes require fresh handle/source/budget validation before use.

Latest same-action evidence supersedes older failed-action diagnostics; uncertain or
stale evidence is not a fresh failure. One failed patch does not forbid all future
repairs serving that desire. Contradictions/conflicts are retained through existing
review context; this projection does not solve or infer semantic incompatibility.
Accepted task completion is not a claim that all standing wants are satisfied.

Deterministic tests cover unchanged reads/restart, competing residuals, withdrawal
and restoration, no eligible desire, pending commitment, passing observations versus
unknown semantic requirements, stale source, closed rejected episode, zero-inference
capacity, exhausted tool reservation, and superseded failed-action diagnostics.
All execution in these tests is a synthetic fake runner; no model or real project
execution was dispatched. They do not demonstrate genuine next-task generation.

Normal proposal requests now include an allowlisted `next_attention` payload. It
contains public criterion/text or an explicitly published semantic-guidance key;
private requirement text, review evidence, posterior values and operator routes
never enter this projection. Unpublished semantic focus produces only a
`operator_guidance_required` marker. Local model context gets version/focus and an
explicit instruction; the controller copies opaque binding metadata unchanged.

Responses must echo `attention_binding`. Application recomputes the factual root,
source snapshot, selected obligation and configuration/admission binding; old source,
withdrawal, foreign binding and replay fail. Current closure, resource stops and
unsettled reservations are checked separately. The request's own measured inference
settlement may consume its final model slot without invalidating its response.
Terminal unknown metering retains conservative charges; it does not become a zero
or a mature/training-eligible measurement. A `Rules`-authored `AttentionConsumed`
record precedes proposal processing in the existing transaction. This records the
context supplied, not proof that a model followed it or fulfilled the desire.

Historical responses remain readable, but an old project response without a binding
cannot be reapplied: obtain a fresh request. Nonproject responses retain the legacy
absent-binding contract. Verification-only admission emits a fresh binding too.
Legacy planning without prospective resource admission remains planning only;
attention cannot install resource authority or authorize execution. New live local
requests still require prospective reservations through the existing budget path.

A newly tested core defect is also repaired: a residual desire with no registered
supporting route formerly crashed project ranking. Such routes now have zero value
and are excluded by the existing commitment filter; the desire remains unresolved.

Cross-episode carry still requires explicit admitted `project init --carry-from` /
acceptance carry. Closed accepted/rejected episodes preserve residual desires but
cannot consume new proposals without fresh admission. Genuine generated continuation
with this integration remains unverified. No live calls/executions occurred; request32
inability and all historical failures remain unchanged. See the bounded validation
plan below. Independent semantic review and eligible mature data remain dependencies.
