# Native open-choice integration: prospective bounded check

This is an integration check on an already approved non-private repair fixture, not a new held-out score or another B9.1 scripted trajectory. Historical results and campaign usage remain unchanged. Start from the original frozen source and its two original requirements, not an evaluator-written failed patch. Protected tests remain outside write authority and outside generator context.

The existing native controller owns current attention, proposal eligibility, choice, commitment and execution. The model can offer alternatives, qualitative relational guidance, a permitted existing verification, or abstain. No experiment-before-patch order, required failure, required novelty or winning patch is supplied. A separately invoked reviewer can reject or express uncertainty; its view grants no new permission and does not establish truth merely by agreeing. Original meanings and explicit acceptance remain traceable.

## Frozen behavioral checks

- Export exactly the approved editable source, public requirements, current applicable generated guidance and attributable bounded returns; never private operator/reviewer notes or protected test bodies.
- The native controller selects among independently reviewed eligible alternatives; no host-selected winning candidate or replacement output.
- If an operation occurs, inspect its actual source-bound receipt and per-case outcomes. Unexecuted assertions and source predictions remain distinct from observed outcomes.
- Request subsequent possibilities from the actual resulting state if unresolved obligations remain and native policy permits. A correct immediate repair followed by review/stop is legitimate; do not manufacture further work to fill the budget.
- If qualitative guidance is offered, review and retain it only through the existing native admission path; it cannot independently authorize an executable action or close a parent desire.
- Preserve failures, abstention, unknowns and every counted request. Restart must not redispatch a known effect or uncertain operation.

The live question is whether current native context can support useful generated alternatives and actual return-informed continuation without a fixed repair trajectory. It does not establish causal TSR advantage, broad reliability, or that rich desires are exhausted by the fixture's predicates. The causal deterministic controls separately hold offers/cost/source fixed and vary attributable return or active obligation. Authored replacement offers and repeated fixture callbacks are not evidence of generated adaptation.

## Bounds and stop conditions

One proposed run may reserve at most eight provider calls (four proposal/review decisions) and four sealed execution groups, inside the existing remaining 19 calls/four groups. Every proposal and independent runtime review counts. CheaperInference `gpt-6-luna` only; 8,192 completion tokens, 240 seconds per call, 32 KiB request maximum; one-hour run deadline and existing 240-second aggregate tool ceiling. Actual campaign remains capped at 200 calls/60 groups/$5, with all earlier usage retained. No commitment is dispatched without native admission and ledger reservation. At the existing conservative $0.05 per-call reservation, eight calls reserve $0.40, not a claimed actual charge or provider billing guarantee.

Stop on invalid response unless a separately tested bounded correction is explicitly included in this same envelope; no automatic uncertain retry. Stop on source drift, denied authority, unknown charge/execution, exhaustion, reviewer rejection/unknown, no eligible choice, or native acceptance/review-required state. Final independent semantic assessment and any formal acceptance remain separate and need not consume a provider call. No source or criteria edits after seeing the result. No extra execution to make a weak outcome look stronger.

This plan alone is not dispatch admission. The exact implementation, fixture/source hashes, runtime, campaign head, payload controls and review findings must be frozen in a fresh run manifest before launch. No paid run was dispatched while writing this plan.
