# Inspect first under partial observability

The contract limitation is established in code, not inferred from model inability.
Previously, `assess_immediate` rejected support without predicted satisfaction
improvement, and `assess_active` offered only a concrete terminal composition as
the alternative. Python excluded unplanned inspection when selected desires
measured account coverage rather than knowledge. PRD B8 explicitly allows Inspect
as the weak-support fallback; requiring unknown downstream content first was an
unnecessary adapter restriction. This does not prove why a provider returned inability.

## Explicit bounded fallback

A generated direction may now carry `deferred_observation`, equal to the current
`observation_revision`, with an Inspect action and **no continuation**. The enclosing
offer must still match the current state root. The two-stage interface freezes this
marker and action before assessment. No action is inserted by the controller.

Every requested note must be admitted and unread, and relevant to an unmet selected
active original obligation. Refinement identities resolve to originals; each support
must have a relevant inspected dependency. Brevity alone cannot justify arbitrary
reading. Exact first-step forecasts are required, including any knowledge predicate
that actually changes. All active original obligations must avoid regression.
Source text remains untrusted evidence; learning its contents does not establish truth.

The existing shared kernel assesses the first-step effects and charges inspection
cost. The explicit `bounded-inspect-first@v1` fallback is considered **only if no
ordinary eligible productive candidate exists in the offer**. Among information
fallbacks, lower charged cost ranks first; there is no invented terminal utility,
probability, gain or calibration. Shared estimates remain diagnostic. The operative
utility's zero value/probability are bookkeeping for an unclaimed terminal benefit,
not a prediction that a later repair has zero chance. Its scope is explicit in the
plan record; the separate first-dispatch forecast concerns actual predicate progress.
Existing policy margin/exploration settings still apply to the eligible support set.

The action consumes one existing cycle and requires capacity for another decision.
There is no reserved terminal action or automatic follow-on permission. A return
records acquired note IDs and measured satisfaction separately. Neutral coverage
is not a successful repair, and unmet desires remain. Restart exposes newly known
evidence for a fresh generated proposal. Repeated inspection, stale revision/root,
withdrawn support and outside scope fail closed.

A conservative singleton-frontier bound avoids demanding a fabricated rival:
exactly one relevant unread ID and no possible improvement of selected originals
from any known-claim composition. Bounds use only known note lengths and admitted
scope. If a known composition might improve an original, two alternatives remain
required. The earlier empty singleton exception remains compatible. This is not a
complete action-space solver. The controller publishes `minimum_directions`; the
local driver uses it consistently in schema and validation.

New traces use `shared-obligation-kernel@v11`; historical records are not rewritten.
The marker is optional and absent in legacy directions. Authority and selection
policy remain separate; this fallback grants no external access.
