# Prospective native pursuit release

This upgrades the existing project controller, not the qualitative reader or a new
scenario-specific loop. Historical admissions, tests and live artifacts stay unchanged.
The frozen design packet remains `experiments/pursuit-evaluation-v1` at its original
manifest identity; this page describes a prospective implementation profile.

The v3 adapter requests advertised JSON-object mode (not guaranteed schema enforcement),
retains bounded privacy-filtered failed bytes through the shared evidence sink, and
uses the shared durable correction allowance. Two corrections are shared across all
generator/reviewer requests. Every correction has a fresh accounted identity and
identical task/context plus structural feedback. Native semantics, source identities,
review verdicts and authority remain fail-closed. Unknown bills/effects stop. Outer
shape and known native shape diagnostics are correctable; other semantic/decoding
errors are terminal rather than guessed or rewritten. Final formal acceptance is
still separate from runtime review.

The v3 controller permits accounted reconsideration at the native `reconsider`
branch. Independent review precedes `advance`; the existing adapter then calls native
`project relational admit` separately, using the exact current binding/proposal.
Only after successful admission does the loop return to ordinary native choice.
It does not require a particular relation, topic, repair or outcome. Legacy local
advisory admissions still stop after reconsideration. Pending effects never replay;
a completed admission checkpoint can reconstruct its bookkeeping marker without
repeating the effect.

Only `engine-native-cycle.py --release-v3` can enter the upgraded live launch path.
Both v3 admissions are mandatory, fixture campaigns are rejected by the live CLI,
and all historical legacy launches remain gated. The flag itself is not approval.
New source pins, explicit origin, native resource admission, campaign scope grant,
remaining-budget preflight and reviewed payload still govern dispatch.

## Scope and exact runtime

The packet loader exports only the frozen public parents, the current admitted Rust
source, exact native IDs/contracts, generated/reviewed lineage and bounded attributable
returns. Tests and private/full state stay outside generation. Supplemental test
creation is deliberately outside this two-operation profile. The runtime uses the
existing pinned image digest
`sha256:cff6dcceb8b9d203a818b7ff104b89a6aaa353f8576850ca4f58903539417945`
instead of the packet's descriptive `tsr-rust:1.90` tag. This is an explicit prospective
runtime derivation; local availability must be rechecked without downloading before
launch. The prospective runtime also uses the existing non-root worker identity **501:20**,
not the frozen draft's 65534:65534. Source inspection found ordinary owner-writable
workspace files and in-container writes, making the draft UID a concrete compatibility
risk. Actual Docker Desktop mapping is not inferred from that inspection. This is
an explicit admission parameter for the future approval, not a host chmod/chown or
security setting change. No automatic image
pull, networked target or external filesystem is admitted.

Four reviewed decisions fit eight ordinary calls; two shared corrections make ten.
Two actualization groups are the maximum, with no separate seed run. Immediate
success or abstention stops honestly. An extra required review must fit this same
budget or stop, not extend it. Native final independent source/receipt assessment
is local and unpaid. A read-only `project cycle response-context` supplies the
current consumption binding after the last settled model call; it is not permission
for a new inference. Unknown/overrun/wall/source guards still apply. The ordinary native branch after a final return may be
`review_required` or an exhausted reconsideration opportunity; neither is claimed
as formal acceptance or successful adaptive meaning.

Future approval remains required: one attempt, ten Luna requests, two isolated groups,
$0.50 conservative reservation, total caps **228 calls / 62 groups / $5**. Current
campaign remains **218 calls / 60 groups / $0.176124**. A prospective grant type only
validates that exact extension; no actual grant or campaign record is applied locally.

After approval and fresh preparation, the supported command is:

```sh
python3 scripts/engine-native-cycle.py --release-v3 check \
  --admission ADAPTER.json --expected-sha256 ADAPTER_SHA256 \
  --cycle-admission CYCLE.json --campaign-manifest CAMPAIGN.json \
  --campaign-upgrade REVIEWED_UPGRADE.json
```

The identical command with `run` in place of `check` is the bounded live launch.
These placeholders are intentional: no fresh live admission or expiry is issued
before approval. Offline callback fixtures use the identical adapter/controller
classes with explicit injected responses and the cfg(test) worker; they do not use
this live CLI with a fixture campaign.

## Local verification and limits

The exact packet completed the native flow with authored provider/reviewer responses
and cfg(test) worker receipts: four reviewed decisions, ten counted stub requests
(including two shared malformed-output corrections), and two fake execution groups.
Reconsideration admission survived interruption and bookkeeping replay without a
duplicate effect. The protected contract compiled offline with Cargo `--no-run`;
its target tests were not executed. This establishes integration, not generated
meaning, real program success or TSR advantage.

Verification: all 15 native cycle tests passed; the final exact-packet/grant checks
passed (2 tests); three additional advisory/crash-boundary controls passed. The
broader Python check initially passed 61 of 62 checks: the new test expected the
wrong terminal branch. It now asserts the actual native
`blocked/proposal_resource_budget_exhausted` stop, and the targeted checks passed.
The exact-cap response-consumption defect found during this work has its own
native regression: an already-settled reviewed response can commit, but another
inference cannot reserve and unknown settlement still blocks consumption.

One earlier authored worker invocation exceeded its unchanged 60-second deadline;
the cause was not established. Subsequent packet runs passed. No deadline was
raised, and the failure is not evidence of a successful real execution. Installed
runtime availability, fresh concrete source/admission pins and current pricing
still require preflight after approval. Historical campaign accounting is unchanged.

Independent final source review found no material release-boundary blocker. It
checked the exact envelope, separate admission, fixture/live isolation and absence
of a prescribed winning action. The final fixture-label test passed: injected
receipts and admission journal are explicitly labeled fixture-only, while live
receipts remain accounted. All implementation, binary and original-design hashes
in the prospective manifest were checked after this change.
