## Contract correction

Rust `World::prerequisites` derives current registration, withdrawal and routed actors,
plus each admitted response's exact required respondent. The normal request contains
these facts and generic per-operation prerequisites. The Python model boundary mirrors
and verifies them, binding the projected facts to the current state root and observation
revision. It rejects an included stale/mismatched projection. Older requests can derive
the same facts from their typed world/history rather than inventing missing observations.

The allowlisted external preparer adds only this prerequisite projection. An offline
comparison established unchanged initial state root, rich parent texts, exact A1,
synthetic world, criteria, model, system instructions and output configuration. No
candidate, ranking, winning sequence or response content was supplied by the correction.
The revision-stage runner rebuilds prerequisites from the actual post-action state.

### Batch policy, unchanged

Rust `Engine::deliberate` already quarantines invalid alternatives and may select from
remaining valid alternatives if its minimum is met; its existing regression test
`invalid_alternative_is_quarantined_without_suppressing_valid_choice` covers that path.
The Python/provider path in these separately admitted trials stops the entire offer
on invalidity before assessment. That stricter admission rule remains unchanged.

Quarantine can preserve useful independently valid alternatives and reduce wasted
work. It also changes the proposed choice set and requires explicit rejection receipts,
a validated assessment subset, preserved source identities and minimum-choice rules.
Silently filtering would hide generator failures and violate this trial's stop rule.
No filtering or batch-acceptance change was made. The earlier mixed offer remains
preserved and rejected; it was not retroactively salvaged or rerun.
