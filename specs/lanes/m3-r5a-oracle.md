## Goal

One item: the oracle must judge the session's copy with tests the session cannot change, on every repository layout. The current design — overwrite each oracle test file in the copy with the snapshot's version — is wrong (the operator's design error, not yours): when tests are inline (`#[cfg(test)] mod tests` in src/lib.rs, the default Rust layout) the file restored is the code under repair, so a correct fix is reverted and a do-nothing session on a mutant task is accepted 5/5 (P1). It also trusts build configuration the session can write: a `.cargo/config.toml` with `runner = "true"` is accepted with the bug present (P2); the "no test matched" guard reads run output from a CAS nothing writes, so it never fires (P3); the restore follows a symlinked directory and writes outside the copy (P4); a listed file the snapshot lacks is skipped silently (P5). Replace restore with a tamper check, then judge the copy as it is. Design to follow: (1) Remove the whole-file restore (run.rs:484-486, 544-594). (2) Before running anything, compare the copy with the task's snapshot (materialise the snapshot read-only beside the copy, or diff against it) and REJECT the session — verdict rejected, reason naming the path — if it added, removed or changed any of: a `Cargo.toml`, `Cargo.lock`, `build.rs`, `rust-toolchain`/`rust-toolchain.toml` or anything under a `.cargo/` directory, at any depth; or if the copy contains a symlink the snapshot did not have. (3) For each oracle test (the task's flipped_tests or failing_tests, each with the file the task records for it in oracle_test_files), parse the snapshot's file and the copy's file with syn, find the `#[test]` function at the same module path in each (inline `mod tests` or a file under tests/), and REJECT if it is missing from the copy or if its tokens differ (compare `to_token_stream().to_string()` of the whole item, attributes included). A test file the task lists but the snapshot lacks is an error at load, not skipped. Nothing outside those functions is compared, so the session may change the code under repair in the same file. (4) Run each oracle test in the copy with `cargo test -- <name> --exact` and read that run's real stdout (not a CAS): pass only when the exit code is 0 AND the output contains `test <name> ... ok` for that exact name; no such line (the filter matched nothing) is a failure. Then the full suite when the task asks for it, exit 0 required. (5) Make the review's table true on two repositories built in the tests — repoA with inline tests in src/lib.rs, repoB with tests in tests/tests.rs — for a mined task and a mutant task on each, through `tsr task run` with no --scripted-runner (use the logging stand-in `tsr exec` the existing m3 tests use): bug present → rejected; bug fixed → accepted (both layouts); oracle test deleted, assertion edited, test renamed → rejected; `.cargo/config.toml` runner → rejected; a `build.rs` added → rejected; a symlink to outside → rejected; do-nothing session on a mutant → rejected.
