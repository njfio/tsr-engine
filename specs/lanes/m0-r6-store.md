## Goal

One item, three small defects lane 01 has carried since M0 landed. (1) **Store discovery.** With `TSR_DB` unset the store is `.tsr/tsr.db` relative to the current directory (store_path.rs `db_path`, `open_store` at :80), so `tsr forecast` or `tsr exec` run from a subdirectory finds no session (exit 2) and creates a second store there; `current_session` (:171) walks ancestors for the session file but the store does not. Rule: with `TSR_DB` unset, use the nearest `.tsr/tsr.db` found in the current directory or its ancestors; create `.tsr/tsr.db` in the current directory only when none exists up to the filesystem root. The session file and the exec lock follow the store's directory. Everything that depends on the store's location (the read-only mount of the store when it sits inside the workspace, the store-equals-workspace refusal) must use the resolved path; test that a `tsr exec` from a subdirectory still gets the store mounted read-only. Tests: from a subdirectory, `tsr forecast` and `tsr exec --candidate` use the root store (one store file exists after), and a fresh directory with no store creates one in place. (2) **`tsr task status` miscounts.** task.rs:46 prints `latest_seq` (the store-wide highest sequence number among the task's events) as the task's event count, wrong once the store holds more than one task: print the number of the task's events (count them; `crates/tsr-store` is not yours). Test with two interleaved tasks. (3) **`tsr forecast --event <id>` is unchecked** (hook.rs `record_forecast_for_candidate` appends a forecast for any 64-hex id): the id must be a candidate proposed in the session's task, else exit 2 naming it and record nothing; a forecast for a candidate that has already run is allowed (it re-arms it — the r5c rule). Test both. Tests first, failing on 6a61b46; then the fixes; ONE commit naming README limitations 3, 7 and 8. Conventional commit; fmt and clippy clean on rust 1.90.
