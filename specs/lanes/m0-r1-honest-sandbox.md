## Goal

One item: M0 must never record a sandboxed run that did not happen, and nothing inside the sandbox may write the event store. Today (main d2b5f96) a runtime counts as reachable when `docker --version` succeeds (exec.rs:78, 96-106), so on a host with the docker CLI but no daemon `tsr exec` records `Dispatched { in_sandbox: true }` and `Executed { exit_code: 1 }` for a container that never started, and exits 1; `tsr hook --selftest` then exits 0 and writes fixtures/m0/session.events.jsonl from runs that never happened — that fixture passes the frozen invariants — and, run from the repository root as the README says, overwrites the committed fixture (hook.rs:782-972). Separately, `container_argv` (exec.rs:113-140) bind-mounts the workspace read-write and the default store is `<cwd>/.tsr/tsr.db`, so a command inside the sandbox can rewrite the event log and the session file. Fix: (1) The probe asks the runtime's daemon, not the binary: `podman info` / `docker info` (quiet, with a short timeout); unreachable → `tsr exec` exits 3 and records nothing, as it already does with no binary. (2) When the runtime is reachable but the container does not start (docker/podman exit 125, 126 or 127 from `run`, or a spawn error), `tsr exec` records `Unresolved` with a reason naming the runtime error — never `Executed` — and exits 3; only an exit code produced by the command inside the container is recorded as `Executed`. (3) The selftest writes its output to a path the caller names (`--out <dir>`, default a fresh temp dir it prints), never into fixtures/m0 unless `--update-frozen-fixture` is given explicitly, and refuses (exit 3, writing nothing) if any of its `tsr exec` runs was not executed in a container. Update m0_harness.rs to use `--out` and to keep comparing against the frozen fixture. (4) `container_argv` mounts the store's directory read-only inside the container whenever it lies inside the workspace — `TSR_DB`'s parent if set, else `<workspace>/.tsr` — as a second, read-only `--mount` over the same path (`type=bind,src=<dir>,dst=<dir>,readonly`); `tsr exec` creates that directory first if missing so the mount cannot fail, and refuses (exit 2) a `TSR_DB` equal to the workspace itself. Tests, all without a real runtime: a fake `docker` on PATH whose `--version` succeeds and `info` fails → `tsr exec` exits 3 and the store gains no event; a fake whose `info` succeeds and `run` exits 125 → `Unresolved` with the reason, no `Executed`, exit 3; a fake whose `run` exits 1 (the command's own failure) → `Executed { exit_code: 1 }`; the selftest with the first fake exits 3 and writes nothing anywhere; the selftest never touches fixtures/m0 without the flag; `container_argv` for a workspace containing .tsr and for a TSR_DB inside the workspace includes the read-only mount after the workspace mount, and for a TSR_DB outside the workspace does not.
