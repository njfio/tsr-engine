## Goal

Repair the corpus, batch and eval half of milestone M3 on branch lane/corpus so that it does what specs/lanes/05-corpus.md says, closing each defect an independent merge-time review found, without touching lane 01's or lane 04's files. Lane 05's bench never ran its two reviews of crates/tsr-eval (deadline tail), and a reviewer of another model family, reading the diff against the brief, found the defects below; the operator confirmed D1 (task.id joined into paths unchecked) and D3 (the oracle runs against the parent snapshot) in the code. Each item is one task. For each: first write a test that fails on the current code and names the defect id (D1 … D10) in its name or doc comment, then make it pass, then commit with the defect id in the message. If an item's finding is wrong, do not change code for it: say so in the task's report with the file and line that show it, and complete the task. Deliver, in this order:
(1) D1 untrusted paths. crates/tsr-corpus/src/mutants.rs is_safe_relative_path rejects absolute paths and `..` but follows symlinks, so a committed symlink (src/x.rs -> ~/.ssh/...) plus descriptors naming it copies a host file into the CAS. Resolve every descriptor path against the repository root with symlinks resolved and refuse any path whose resolved form leaves the root or passes through a symlink. crates/tsr-batch/src/run.rs joins the untrusted task.id from tasks.jsonl into out/state/<id> and out/copies/<id> (an absolute id replaces the base), and batch_cmd.rs reads the same way: a task id is [A-Za-z0-9._-]{1,128} and not "." or "..", refused with exit 2 otherwise, checked where tasks.jsonl is parsed. Tests: a symlink to a file outside the repo, an absolute task id, a "../" task id.
(2) D3 the oracle judges the session's work. run.rs runs the oracle with task.snapshot() (the unmodified parent) as its working directory, and the CLI hardcodes ScriptedRunner::ok(), so completion can never differ between systems (the denied rules run is still "accepted"). Run the oracle in the session's copy (`dest`), and make the CLI choose its Runner the way corpus mine does (ExecRunner by default; ScriptedRunner only behind an explicit test flag). Test: a session that leaves the flipped test failing is not accepted; one that fixes it is.
(3) D4 mine checks out what it claims. mine.rs runs the suite at the parent and at the commit with the same repo path and argv, and parent_snapshot is the digest of the suite's stdout. Through the Runner: materialise the parent and the commit as separate worktrees (or archives) under the output directory, run the suite in each, and set parent_snapshot to the parent commit's tree id (git rev-parse <sha>^{tree}). Remove or implement the `tsr corpus materialize` / `tsr corpus oracle` invocations that do not exist as subcommands; check the provisioning exit code. Test with a two-commit repository in a tempdir and a Runner that executes git for real (git only, no cargo).
(4) D2 cost per accepted completion. baseline.rs prints ratios of sums but computes the paired difference, its interval and the verdict from per-task "cost if accepted, else 0", and cluster_bootstrap only averages. Define the metric once (total cost of accepted tasks / number accepted, per system), compute the paired difference as the difference of the two ratios, and make the cluster bootstrap resample lineages and recompute both ratios per resample; a system with no accepted task reports the metric as undefined ("n/a"), never 0. Test against a hand-computed example whose ratio-of-sums and mean-of-ratios differ in sign.
(5) D5 one lineage is never "clear". With fewer than two lineage clusters every resample is identical and the interval has zero width: report "interval n/a — 1 lineage" and INCONCLUSIVE. Test.
(6) D8 paired results. `tsr eval baseline` takes the two runs it compares (`--record <dir> --rules <dir>`, or one results file holding both systems), pairs by task id, and reports unpaired tasks; the README and the evidence use the command that the CLI accepts. Test the documented invocation end to end over fixtures/m3.
(7) D6 the Tier 0 controller. Rules mode replays a fixture's steps through the gate; nothing implements PRD §B9's Tier 0 policy (inspect until the failing assertion and its call site are read, then run the test, then propose; stop on budget; a denial ends the attempt, it does not continue). Implement it behind the Driver trait for the rules system, test the three rules (read-before-test, budget stop, stop on denial) with a scripted repository.
(8) D9 mutants task content. Each mutant task carries the failing tests of its own kill run (not one shared report); a cargo-mutants exit that means "some mutants missed" is not a failure of the command (read cargo-mutants' documented exit codes from its --help or docs in the sandbox and cite them in a comment; if unavailable, treat only spawn errors and a missing mutants.json as failures); read the mutant list from where the invocation actually writes it (stdout with --list --json, or the file — make the doc and the code agree); the stored reversal is a real unified diff.
(9) D7 and D10 evidence and leftovers. docs/m3-evidence.md is re-captured verbatim from runs on this branch — every command in the original brief's acceptance list and the eval output with its footer, unit, direction and proxy lines — nothing hand-edited; the mine example uses the committed test fixture or says exactly which repository it ran on. D10: re-running into an existing --out starts from empty stores (or refuses); Unavailable results are excluded from completion with a count; DuplicateTask names the duplicate; `tsr task run` resolves profiles/default.toml from the repository root, not the working directory. Every number the eval prints goes through the tsr_domain Proxy with its engineering term (Appendix A).
No change to lane 01's or lane 04's files; no tsr-policy change; no network crate; conventional commits; fmt and clippy clean.
Operator notes: a create_task refused three times with the same text is a signal, not a retry — stop, post the refusal to the operator, and wait. A passing command is recorded once; do not run a green test again to confirm it. await_task waits at least 60 seconds. Start every command with `export PATH=/usr/local/cargo/bin:$PATH CARGO_HOME=$PWD/.cargo-home` (rust 1.90 with rustfmt and clippy); .cargo-home/ and target/ are build caches — never commit them, exclude them from grep and surveys. If a cargo command reports "can't find crate", run it once in CARGO_TARGET_DIR=$PWD/target-fresh instead of repeating it (Docker Desktop's file cache, not a code fault). Every file write goes through the sandbox, never a host path. A landing commit holds deliverable files only. A review verdict names the file, the line and the behaviour it saw. Dependencies on a Pending task are allowed; a task held past its estimate with no evidence is failed, not extended. Review tasks are created after a landing exists; if create_task refuses with clause (jj), move on and delegate the ready tasks. No reply needed.
