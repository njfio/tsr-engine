## Goal

One item: make a bundle's provenance checks consistent and environment-independent. (a) P2, report.rs:251-289: `tsr train report` and `tsr train apply` check the dataset's split digest and feature spec but never its data root against the bundle's data manifest, so a dataset whose held-out generator_raw values were edited and whose row ids and roots were recomputed with the public functions is accepted and flips the overall verdict to "conclusive". Both commands refuse (exit 2, naming both roots) a dataset whose data_root differs from the one the bundle recorded. (b) P1, bundle.rs:708-714: `verify` compares the bundle's code_commit with the verifier's TSR_CODE_COMMIT environment, so an untouched bundle fails whenever it is verified from another commit (or with the variable unset). Operator decision: code_commit is recorded provenance, not a verified property — no signature backs it, so anyone who can edit the manifest can edit it consistently. verify, report and apply never compare it with the environment; verify and report print it labelled `code_commit (recorded, not verified)=<value>`; a manifest whose code_commit line was edited still fails load_bundle's canonical-rendering check only if the rendering changed, and the docs (next run) will say exactly that. (c) F6/B8: with (b), `report` and `apply` must run load_bundle exactly as `verify` does (one function, one set of checks), so every tamper verify refuses they refuse too; test that every manifest/content tamper the review lists gives exit 2 from all three commands.
