## Goal

One item, with an operator decision. Three rounds tried to make the hook's view of a Bash command and `tsr exec`'s argv agree (r2 digests, r3 shell emulation, r4/r4b pattern matching); each fixed the named spellings and broke others (r4b: a newline inside a quoted argument breaks the pattern sidecar; a forecast's text replaces the hook's pattern; `<<<`, `[ab]`, quoted `'*'`). **Decision: nothing is matched. The agent names the candidate.** (a) `tsr forecast --kind <k> --args <text> --p <p>` already prints an id: make sure it is the candidate id, printed alone on stdout, and that the candidate is recorded as proposed with that forecast at the current state version. (b) `tsr exec` gains `--candidate <64-hex>`: `tsr exec --candidate <id> -- <argv…>` binds the run to that candidate — it must be a candidate of the session's task that has a forecast and is not yet dispatched; exec records `Dispatched` and `Executed` for it and runs argv as today. An unknown, unforecast or already-dispatched id exits 2 naming the reason and runs nothing. (c) The hook, at PreToolUse for a Bash command, tokenizes the command with the existing grammar-only parser (quotes, escapes, separators, here-documents as data, comments) and, if it finds a `tsr exec` invocation carrying `--candidate <64-hex>`, commits that candidate (records `Committed` for it at the current state version) and records no new proposal. No pattern, no sidecar, no matcher: delete the pattern sidecar (`.tsr/patterns.jsonl`), the `Pattern` type and `pending_matching`, and any code that only served them. (d) Without `--candidate`: the hook records the Bash call as it does for any non-gated tool (proposed generate, then committed), and `tsr exec` mints its own candidate with no forecast and prints one stderr line saying the run has no forecast because no `--candidate` was given — the log is honest about it, and reconstruct may reject it; that is the intended signal. (e) Classification of plain `cargo test` / `cargo nextest run` spellings as test runs stays as on f9c64dd. Tests, through `tsr hook` and `tsr exec` with the m0_ordinary_session.rs harness and a real `bash -c` running the command after PreToolUse: for each spelling below, forecast with `tsr forecast`, then the Bash command `tsr exec --candidate <id> -- …`: one proposal, one forecast, one commit, one dispatch, and a log reconstruct accepts — `cargo test 2>&1 | tail -20`, `… > out.txt`, `cat "$HOME/x"`, `ls ~`, `ls *.toml`, `sh -c 'a; b'`, `sh -c "a⏎b"` (a newline inside quotes), `git commit -m "t⏎⏎body"`, `cat <<< "hi"` before it, `ls [ab].toml`, `echo '*'`, `find . -exec echo {} \;`, `time` / `timeout 60` / `nice -n 5` before `tsr exec`; an unknown or already-dispatched `--candidate` exits 2 and runs nothing; `tsr exec` without `--candidate` prints the stderr line and records a candidate with no forecast; no input panics the hook (5,000 random strings). Update m0_matcher.rs's tests to the new protocol or remove the ones that only tested matching.
