## Goal

Repair milestone M2 (Reflect) on branch lane/reflect so that it does what specs/lanes/04-reflect.md says, closing each defect an independent merge-time review found, without touching lane 01's M0 files. Lane 04's bench passed the code, but its reviews of the Filter, reconcile, note and the fixtures never ran (deadline tail), and a reviewer of another model family, reading the diff against the brief, found the defects below; the operator confirmed D1 and D2 in the code. Each item is one task. For each: first write a test that fails on the current code and names the defect id (D1 … D12) in its name or doc comment, then make it pass, then commit with the defect id in the message. If an item's finding is wrong, do not change code for it: say so in the task's report with the file and line that show it, and complete the task. Deliver, in this order:
(1) D2 admission by source: crates/tsr-ledger/src/active.rs folds every StatusSet regardless of `by`, and write.rs set_status guards only withdrawn/out_of_scope, so a StatusSet(Open) by Generator (or mark_fulfilled by Rules) admits a Generator-origin preference. A Generator-origin preference is in the active view only after a StatusSet(Open) whose `by` is Operator; a non-operator Open on it is recorded and ignored for admission (test both). Statuses that are mechanical (fulfilled, overlapping) apply only to preferences already admitted.
(2) the common decision event id: crates/tsr-forecast/src/outcomes.rs mints `Hash::of(&[name, version.to_le_bytes()])`, but main's hook (crates/tsr-cli/src/hook.rs, DECISION_EVENT) mints `Hash::of(&[b"task_accepted_in_budget@v1"])`, so every forecast the hook records is never scored. Make outcome_def_id(name, version) = Hash::of(&[format!("{name}@v{version}").as_bytes()]) for every named event, use it everywhere (review_cmd.rs mints diff_accepted@v1 by hand — route it through outcome_def_id), and add a test that tsr-forecast's common_decision_event_id() equals the id main's hook records (read it from a hook-recorded fixture event, e.g. fixtures/m0/claude-session.events.jsonl's forecast `event` field).
(3) D3 the review rejection path: review_cmd.rs hashes (subject, reason) into a ContrastId but never writes a Contrast, and Ledger::expand accepts any ContrastId, so the only production expansion bypasses the Filter. A rejection writes the Contrast { unmet: Rejected(reason) } through the Filter and expands from it; Ledger::expand refuses (exit 2 at the CLI) a ContrastId with no Contrast event in the log, and refuses a Contrast with no unmet criterion. Test both refusals and that the Mirror's Contrast section shows the rejection.
(4) D1 reconcile from the CLI: reconcile_cmd.rs builds ToolCheck::new(cas_root) with no digests, no seen keys and nothing idempotent, so every pending dispatch is "non-idempotent, blocked" and, once Unresolved, never re-checked. Load the ToolCheck's evidence from the log and the CAS (log digests of Executed events present in the CAS; idempotency from the action kind — RunApprovedTest is idempotent); an Unresolved{blocked} dispatch is re-checked on every reconcile until a check resolves it; "retry once" for an idempotent unknown is enforced (a second retry refuses). CLI tests for each path.
(5) D5 the crash matrix: the acknowledgement crash point is never exercised (FakeExecutor::reconcile is never called) and the forecast UPDATE is attempted before Executed exists. Drive each of the three crash points through the reconciler, assert at most one Executed per idempotent dispatch for each, and attempt the forecast UPDATE after Executed, asserting the store's specific refusal (not just is_err) while an outcome append succeeds.
(6) D4 review statistics: `tsr review --family <f> --stats` must not require a task; it computes over every task of the family. The false-accept rate counts only greens (returns whose own outcome passed) that a reviewer rejected; failed returns are not "green". D8: `--sample` draws only over greens and records the inverse-probability weight on sampled greens only; `--return <id>` is checked against the task (UnknownReturn exits 2). D7: `rejected` is its own LabelStatus (do not reuse Invalid); resolve.rs maps Invalid to invalid, not to rejected.
(7) D10 resolution: resolve.rs's common event ignores the budget and the criteria; the operator-stop censoring branch is unreachable; pipe_evidence does nothing; the Committed arm does nothing (intuition_selected/executed resolve false at close). Implement each per §B7's table (true only when criteria met, diff accepted and no budget ceiling breached; censored on an operator stop or never reviewed), with a test per row. D11: the residual is forecast minus observed, as the brief says (filter.rs, score.rs), with a test of the sign.
(8) D9 the Mirror: Surprise rows name their forecaster; propensity comes from the commit record; Belief lists the committed candidate's forecasts only; Desire's intent is the task's intent (TaskOpened), and operator notes are listed as notes (use notes_for). D12: `tsr note` on a task the log does not hold exits 2.
(9) D6 fixtures and evidence: the m2 episode JSON is regenerated only by an explicit TSR_REGEN_FIXTURES=1 and otherwise compared read-only (the test must not overwrite fixtures/m2/store/tsr.db or the JSON before comparing); docs/m2-evidence.md is re-captured verbatim — every command in the brief's Definition of done, including `tsr reflect <task>`, `--json`, `review rejected`, `note`, `task reconcile` and `reflect --family` with its bins — from runs on this branch, nothing hand-edited. Remove `write_corpus` if unused (dead_code under -D warnings).
