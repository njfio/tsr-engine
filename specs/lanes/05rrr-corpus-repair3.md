## Goal

Close what the independent review of lane 05rr found on lane/corpus. The review confirmed mined-task provisioning, R1, R2, R3, D6, D8, D10, the mutants list and R5 fixed in behaviour. The central requirement of M3 is still unmet after two repairs: a session must work in a disposable copy of its task, and the oracle must judge that copy with tests the session cannot change. Items (1) and (2) are that requirement, written as a design to follow, not a goal to interpret; do them first, in order, each on one worker. Each numbered item is one task: first a test that fails on the current code and names its ids, then the fix, then a commit with the ids in the message. If a finding is wrong at the tip, report the file and line that refute it and complete the task. Deliver, in this order:
(1) D3 the session works in the copy. Driver::drive (driver.rs:128-133) receives no copy, and run.rs:375 never passes one, so a session's edits never reach `dest`. Add the copy's absolute path to what drive receives (SessionCtx or an argument); every session step that touches files or runs a command runs with that path as its working directory and only there — the ScriptedDriver applies its scripted edits inside the copy and the Claude Code driver launches the agent with the copy as its working directory. Test, through `tsr task run` with no --scripted-runner on a task mined from a real repository built in the test: a scripted session whose step fixes the bug leaves the fix in the copy, and the oracle then accepts.
(2) D3 the oracle judges the copy with the snapshot's tests. No code restores the oracle files today, so a session that deletes the flipped test, edits its assertion or renames it passes with the bug still present (review table: deleted → pass, edited → pass, renamed → pass with the filter matching nothing). Each task records the repository paths of the files that define its oracle tests: mine takes them from the commit's diff (test files and files with `#[test]` functions that changed), mutants from the suite that killed the mutant; a task without them is refused at load, not judged. Before the oracle runs, those files are written into the copy from the snapshot (overwriting the session's versions), and a filter that matches no test is a failure, not a pass. Make the review's table true: bug present → fail; bug fixed → pass; test deleted, assertion edited, test renamed → fail. Test each row through `tsr task run`.
(3) D4, D9 mutant tasks that provision and reverse. `tsr corpus mutants` writes mutated_snapshot = blake3 of the descriptor (mutants.rs:755) and neither base_snapshot nor mutation_diff, so task run fails at provisioning and the batch exits 2; run.rs:363 reads the mutation diff from the batch's --out CAS, not the corpus's, and run.rs:362 skips it when dest is missing; reversals are built from outcomes.json descriptors that carry no diff, so 0 of 5 pass `git apply --check`, and the diff path copies the `@@` header unswapped (mutants.rs:566-569; `corrupt patch at line 12`). mutants records base_snapshot (the tree id it mutated) and mutation_diff (a CAS key in the corpus directory's own cas/, which task run reads from beside tasks.jsonl); provisioning materialises the base and applies the mutation diff, and fails the task (not the batch) if either step fails; the reversal is produced by `git diff` between the mutated copy and the base copy (never by editing diff text), so it applies by construction. Test end to end on a real repository with a stand-in cargo-mutants: every reversal passes `git apply --check`, and `tsr task run` provisions every mutant task.
(4) N2, N3, N5 the sandbox boundary (PRD B10: the disposable copy is the only writable mount). Provisioning runs with cwd = <out>/copies, the whole copies root, and passes relative paths unresolved (a relative --out lands the copy in brel/copies/brel/copies/… and the task is silently recorded rejected; a repo mined by relative path cannot be materialised); a real `tsr exec` cannot read the source repository (only its cwd is mounted) and is given no TSR_SESSION; and `tsr corpus mutants` runs the kill run with the operator's repository as the writable mount and leaves mutants.out/ in it (mutants.rs:700, 712). Decision: provisioning is a trusted host step — the runner materialises the snapshot into the task's copy itself (git archive from the repository, which is only read), never through tsr exec; every tsr exec the batch issues (session steps, oracle) runs with cwd = that one task's copy and with TSR_SESSION set as exec.rs requires; the mutants kill run happens in a disposable copy materialised from HEAD, never in the repository, and leaves nothing in it. All paths are made absolute before use. Test with a logging stand-in `tsr exec`: every invocation's cwd is one task copy — never the repository, never the copies root — and `git status` in the repository is clean after mine and after mutants; a relative --out and a relatively mined repo both work.
