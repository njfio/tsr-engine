## Goal

One item. Operator correction: r5b's brief said exec refuses a candidate that has any `Dispatched` "whatever came after it". That was wrong: a candidate id is (kind, args digest), so the same command forecast again later gets the same id, and the rule made a command impossible to run twice in a task — fixtures/m0 itself runs one candidate twice, each time after a fresh forecast. **Rule: one forecast authorizes one run.** A candidate is dispatchable when its latest `Forecast` comes after its latest `Dispatched` (or it has never been dispatched) and it has been committed after that forecast. The hook commits a named `--candidate` only under the same condition; otherwise it records an ordinary call with one stderr line why; exec refuses (exit 2, runs nothing) otherwise.
